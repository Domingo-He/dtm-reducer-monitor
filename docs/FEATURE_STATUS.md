# 功能狀態表

DTM v2.1.0（Beta）・2026-10-19 更新

> **一句話：程式都寫好了，也在模擬資料上測過；還沒有接過真的機器人，也還沒有在產線驗證過判斷準不準。**

**狀態**

| 標示 | 意思 |
|---|---|
| ✅ 完成 | 程式已實作，可以使用 |
| 🧩 範本 | 機器人端程式或範例：要依你的控制器修改、教點，並先在實機確認 |
| ⏳ 未做 | 還沒做，以後可能做 |
| ⛔ 不做 | 刻意不做，理由見 [設計邊界](DESIGN_CONSTRAINTS.md) |

**驗證**（✔ = 做過，— = 還沒有）

| 欄位 | 意思 |
|---|---|
| 測試 | 有自動測試。`python -m unittest discover -s tests` 共 233 項全部通過（開發環境 Linux、Python 3.13，2026-10-19）。GitHub 倉庫建立後，每次推送也會在 Windows 與 Linux、Python 3.11–3.13 自動執行 |
| 模擬 | 用內建模擬器或演示資料把流程跑過，並在瀏覽器（Chromium）看過畫面 |
| 實機 | 接過真的 FANUC 控制器（R-2000iC/165F）讀到資料、跑過流程 |
| 現場 | 在產線長期執行，判斷結果跟拆檢或失效紀錄對照過 |

v2.1.0 的「實機」與「現場」兩欄全部是「—」。這兩欄要等有人實際導入、回報結果後才會更新。

## 實機驗證要先確認的事

第一次接實機時，依序確認下列項目；確認後在本表把對應的「實機」改成 ✔，並記下控制器版本與日期。

1. **干擾扭矩變數**：`$MOR_GRP[1].$CUR_DIS_TRQ[n]` 讀得到，數值跟示教器 STATUS → Axis 的干擾扭矩畫面一致。
2. **背景邏輯**：`DTM_BG` 在 BG Logic 持續執行，心跳 R[112] 一直增加，速度倍率 R[113] 正確。
3. **讀取方式**：`http://機器人IP/MD/NUMREG.VA` 打得開，`check --connect` 全部 ✔；確認每秒 2–5 次讀取不影響控制器。
4. **診斷程式**：`DTM_DIAG` 跑完後，儀表板看得到每一段，5% 速度的等速段至少 4 秒。
5. **導入檢查報告**：跑滿 7 天，取樣、中斷、切段、雜訊都 ✔。
6. **通知**：用工廠實際的郵件伺服器、簡訊數據機或簡訊商各發一次測試通知。
7. **Windows**：在現場電腦上安裝成服務，重開機後會自動啟動，看門狗正常。
8. **Pro**（要做時）：加註版程式上傳後動作不變；R[114] 行號回報正確；確認控制器有沒有開放傳遞扭矩；KAREL 串流或其他高速取樣方式可用。

**現場驗證**（v3.0）：影子模式至少 1–3 個月；每次換件都填拆檢表單；用「現場驗證報告」看偵測率、提早天數、漏報與誤報。

## English summary

**Feature status of DTM v2.1.0 (Beta).** The PC-side features are implemented and, unless the table says otherwise, covered by the automated test suite (233 tests passing on Linux, Python 3.13, 2026-10-19; CI on Windows and Linux with Python 3.11–3.13 starts once the GitHub repository exists); most were also run end-to-end on the built-in simulator or demo data and checked in a Chromium browser. Actual e-mail sending (SMTP) has no automated test. **Nothing has yet been connected to a real FANUC controller, and no judgement has been validated against field failures**: the "real controller" and "field" columns are empty for every feature. Robot-side programs (`DTM_BG`, `DTM_DIAG`, `DTM_SWEEP`, motion-code example, KAREL stream) are templates that must be adapted and verified on the controller. Notifications were tested against mock servers and a fake serial port; Windows service files and launchers were checked for content and encoding but never run on Windows; the Windows portable build has not been produced yet. English, Japanese, Korean and Vietnamese translations are AI-made and not reviewed by native speakers. Thresholds, evidence weights and work-package hours are experience-based examples. Not yet done: field validation (target of v3.0), AI-written Pro suggestions, other robot models and brands, OPC UA, local messengers. Deliberately not done: writing to the controller, automatic program changes or speed reduction, replacing measurement with simulation, single-evidence replacement advice, millisecond spectral analysis (see `DESIGN_CONSTRAINTS.md`). A checklist for the first real-controller test is at the end of this document.
